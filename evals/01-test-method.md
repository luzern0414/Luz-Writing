# 01 · 测试方法

回归用例在 `evals.json`。这些用例覆盖事实边界、定点编辑、保声改写、小说连续性、学术引用、选题增量、核查状态、科普准确性、非虚构伦理、只交付要求的文案、输出目录结构、资讯表达、交易文案的文案键表、协议里的事实缺口，“先读规则卡再回复”，以及客户文件（方案说明书、使用说明、业务逻辑确认表）、国标标点与数字、GB/T 7714—2025 参考文献、平台标题限制和 AI 生成内容标注、引语处理。

26—33 补充材料理解与四类场景：版本冲突、表格注释与条件、图文页职责、公众号主轴、整本宣传手册、广告压缩、跨渠道事实一致，以及未读材料的诚实边界。文件中是待运行的评测定义，不代表所有用例已经执行通过。

## 人工验收顺序

1. 只在上下文中提供对应提示和必要材料。
2. 不先提示模型应该读哪份 reference。
3. 检查它是否先运行 `scripts/06-context.py <类型>` 读了对的规则卡（选卡是否合适、是否读完），而不是凭模板或记忆动笔。
4. 用 assertions 做客观检查。
5. 回到原材料逐项核对主张、推导与条件，再人工评价声音、结构和可发布性；文风不能只靠自动断言。
6. 对失败案例先定位是选卡、规则、材料还是模型执行问题，再做最小修订。
7. 规则修改后至少回归受影响用例和两个无关用例，防止局部修复破坏其他文体。

## 通过标准

- 事实边界：不把传闻、截图或厂商声明升格；状态用 02 › 声明分级的五个词，缺口用 `[待核实：缺什么]`。
- 范围边界：审稿不自动改写，定点编辑不改范围外内容，写作和改写不附建议、审计或改动说明。
- 输出目录：会话位置和根目录内容符合 [16](../references/16-output-paths-and-tools.md) › 会话结构与项目任务，`03-session.py check` 通过。
- 原意保真：数字、否定、因果、责任与人称不被偷换。
- 叙事因果：视角、状态与选择一致。
- 自然度：至少消除最明显的假对比、机械排比、空泛升华和格式装饰。
- 表达：按题材、读者和声音样本判断自然度；科技资讯采用自身的数字预算，规格表、教程与解释文保留必要数字，不强制每篇加比喻和短评。
- 渠道：标题、摘要、CTA 和正文彼此兑现。
- 界面文字：以文案键表交付，每条不超过字数上限，只用登记的变量。
- 客户文件：正式客户方案按 18 的专用规则先分析需求再给方案，没有价格、他文件指引、技术词和占位；确认表给出可确认的拟定逻辑，不预填客户的回答。产品宣传手册按 24 判断，不能套入客户方案的所有限制。
- 中文文字：标点、数字、日期符合 GB/T 15834、15835；参考文献按现行的 GB/T 7714—2025；引语不改原话，译文标明为译或转述。

## 理解与场景评审

先把客观约束列成检查表：材料覆盖范围、产品与版本、否定和例外、数据口径、数量与篇幅、指定字段和改动范围。评审人自行回到原文定位，不以理解表填满代替核对。压缩或跨渠道改写后重新核对限制，多个转载不计为多个独立证据。模型尚未读取的文件和模糊图片不能计入已覆盖资料。

| 交付场景 | 人工看什么 |
| --- | --- |
| 图文笔记 | 每页是否新增信息，页序是否可理解，配文是否补充背景，是否虚构亲测 |
| 公众号 | 是否围绕一个问题推进，各段是否承担不同任务，标题与结尾是否兑现正文 |
| 宣传手册 | 整本是否支持客户判断，每页是否有职责，版本和承诺是否一致，是否凑口号页 |
| 广告 | 主信息是否清楚，必要条件能否与利益同读，CTA 是否真实，是否借用了其他型号能力 |

同时保存实际输出、选卡、客观核对结果和人工判断。相同材料与请求可做改前改后比较；旧版已通过的项目如实保留，不能编造成失败。少量试写只说明这些样本的行为；若要判断稳定改进，需对代表性输入多次独立运行并比较成功率、声音与结构，不据单次通过宣称质量普遍提升。

修改共用规则时至少包含一次多材料任务、一次条件压缩任务，以及两个无关旧任务（例如定点编辑和小说连续性）。独立试写应先读入口与所选规则卡；内部演练可只读装配卡片，不创建业务会话、联网或写经验，但必须保留选卡与阅读范围，不能因此声称已走完业务交付协议。

## 自动验证

`scripts/01-validate_skill.py` 检查包结构、编号、链接、评测用例格式、规则卡（每张卡都能切出规范原文、共享核心与 Luz-Design 一致、SKILL.md 以调用协议开头）、经验库（结构、重复、超限、个人信息），运行下面全部测试，并跑一次从建会话到打包的冒烟测试。`scripts/07-test_context.py` 测规则卡、范围与交付类型的选卡优先级、显式选卡、新会话理解记录、打包卡口、项目状态根解析、导入 Luz-Crawl 任务目录和 builder 的版式；`scripts/05-test_experience.py` 测经验库；`scripts/10-test_text_check.py` 测中文文字检查（`scripts/09-text_check.py`）；`scripts/11-test_crawl_gate.py` 测项目阶段完成后的检索过期豁免；`scripts/test_article_output_boundary.py` 与 `scripts/test_summary_generation_gate.py` 用 pytest 测 `--out` 的输出边界和汇总页的检索卡口。自动验证不会运行全部行为用例，也不证明一篇文章事实准确或写作质量提高。

测试与演练可设环境变量 `LUZ_EXPERIENCE_STORE=<notes.json 路径>`，把经验命令、规则卡和沉淀检查临时指向测试文件，正式经验库不动；真实交付不得设置它。替客户调用本技能的程序只在批准后记通用经验，先搜索再确认，不记录客户上下文。
