# 01 · 测试方法

回归用例在 `evals.json`。这些用例覆盖事实边界、定点编辑、保声改写、小说连续性、学术引用、选题增量、核查状态、科普准确性、非虚构伦理、只交付要求的文案和输出目录结构。

## 人工验收顺序

1. 只在上下文中提供对应提示和必要材料。
2. 不先提示模型应该读哪份 reference。
3. 检查它是否选对路线并按需读取，而不是一次加载全部文件。
4. 用 assertions 做客观检查。
5. 人工评价声音、结构和可发布性；文风不能只靠自动断言。
6. 对失败案例先定位是路由、规则、材料还是模型执行问题，再做最小修订。
7. 规则修改后至少回归受影响用例和两个无关用例，防止局部修复破坏其他文体。

## 通过标准

- 事实边界：不把传闻、截图或厂商声明升格。
- 范围边界：审稿不自动改写，定点编辑不改范围外内容，写作和改写不附建议、审计或改动说明。
- 输出目录：会话位于 `D:\Codes\skill输出\Luz-Writing\NNN-主题\`，根目录只有同名 HTML 和 `raw/`。
- 原意保真：数字、否定、因果、责任与人称不被偷换。
- 叙事因果：视角、状态与选择一致。
- 自然度：至少消除最明显的假对比、机械排比、空泛升华和格式装饰。
- 表达：资讯与观点稿有画面、有态度、有对话感；数字守预算，不出现数字堆和报告腔。
- 渠道：标题、摘要、CTA 和正文彼此兑现。

自动验证只检查包结构、链接、编号、HTML 打包冒烟、经验库（重复、超限、个人信息）及其单元测试，不证明一篇文章已经事实准确。
