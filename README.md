# Luz Writing

写给一个读者、一个目的、一个渠道的中英文写作技能：事实可查，表达自然，只交付要的内容。

## 能做什么

- **起草与改写**：科技资讯、营销文案、观点与科普、故事与小说、学术与专业文档、用户协议与隐私政策，以及各平台的标题、摘要和格式适配。
- **交易与运营文案**：小程序和 App 里的优惠弹窗、门店与停业公告、券规则、价格说明、活动规则和续费说明，按文案键表交付（键、页面与位置、文案、字数上限、变量），供后台维护和开发种子使用。
- **事实核查**：数字、引语、日期、名称逐条对应来源；搜索摘要只算线索；查不到的内容标成 `[待核实：缺什么]`，不编造。
- **去机器腔**：改掉空话、套话、排比堆砌和报告腔，没问题的句子原样保留，不矫枉过正。
- **只交付所要**：要几条、多长、什么格式就给什么，不附建议、评分、改动说明或备选版本。
- **成稿与配图**：成稿打包成一个阅读型 HTML，版式遵循 Luz-Design；需要封面时从风格菜单选风格（默认 3D 潮玩、软陶质感），用本机图像生成服务出无文字底图。
- **越用越懂你**：每次调用后记下偏好、有效来源和教训，下次先查再写。

## 适合 / 不适合

适合：以文字为主的交付，包括文章、文案、协议正文、标题、摘要、脚本、审稿和事实核查，以及文章自带的封面和插图。

不适合，请转到：

- 海报、品牌主视觉、文档与表格版式的设计细节 → Luz-Design
- 产品界面、系统方案、原型和硬件选型，以及按钮、空状态、确认框这类界面用词 → Luz-System
- 后端开发、部署和上线，以及协议的版本、同意记录与撤回 → Luz-Dev（协议正文和上线文案仍由本技能写）
- 网页检索与采集 → Luz-Crawl（本技能调研时会调用它）

## 快速开始

1. 把本目录放进 Agent 的技能目录（例如 `~/.claude/skills/luz-writing`）。
2. 准备 Python 3.11 及以上。调研需要 [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl)，排版与海报需要 [Luz-Design](https://github.com/luzern0414/Luz-Design)；配图是可选能力，需要本机的图像生成服务。
3. 直接用一句话提需求，例如：
   - “把这几条发布会信息写成一篇公众号科技快讯，配一张封面。”
   - “这段读起来太像机器写的，只改这一段。”
   - “给这个产品写三条小红书标题。”
   - “核查一下这篇稿子里的数据和引语。”

安装后可以先跑一次自检：

```text
py -X utf8 scripts/01-validate_skill.py
```

## 工作方式

1. **先读规则卡**：按任务类型运行 `py -X utf8 scripts/06-context.py <类型>`（`list` 看全部类型，如科技资讯、营销文案、润色审稿、事实核查、封面配图），读完卡上的用户偏好、相关教训、写作指南原文、该用的工具和交付前检查。模板、示例正文和打包脚本只是骨架，与规则卡冲突时按规则卡；只在对话里回一段文案时也先读卡。
2. **查经验**：规则卡已带上全部偏好和相关教训，再按这次的话题和渠道搜一次经验库。
3. **定任务**：判断是起草、改写、定点修改还是审稿；规则卡没说清的地方再读对应写作指南的原节。
4. **找依据**：需要事实时用 Luz-Crawl 读原文（按它的调用协议先建任务目录），把说法、来源、日期和支持状态记进声明表。
5. **起草与修订**：从主旨、结构、段落到句子、用词、标点，由大到小改。
6. **过质量关**：事实、表达、格式和“只交付所要”逐项检查。
7. **交付**：每个任务一个目录，只交付一个 HTML，资料、草稿和图片放在旁边的 `raw/`。建会话时规则卡自动存进 `raw/00-rules/`；简报里的“采用的规则”和“本次沉淀”没填，打包脚本就不生成成品。
8. **沉淀**：每次调用结束前至少写入或确认一条经验（新偏好、规则纠正、有效写法、调研来源与范围、生成参数），已有经验再用上时用同一个 key 再写一次即确认。

## 经验沉淀

Luz-System、Luz-Design、Luz-Dev、Luz-Writing 四个技能用同一套经验沉淀：经验库是 `experience/notes.json`，每条有主题键 `key`、类别 `kind`（偏好 preference、教训 lesson、有效信息 fact）、一句话原则 `text`、可选依据 `why`、确认次数 `uses`、首次记录 `first_seen`、最近确认 `last_confirmed`，被替换过的再带一条旧说法 `previous`。开始时用 `search` 查，结束前用 `note` 写，另有 `list`、`prune`、`check`（本仓库脚本 `scripts/04-experience.py`）。同一主题再写会替换旧说法，同一句话换了键只算再确认一次；偏好最多 60 条，教训和有效信息各 120 条，超出时先删确认最少、最久没确认的，180 天没确认的会列出来。仓库公开，手机号、邮箱、微信号、个人目录路径和密钥写不进去，检查也会拦下。

每次调用至少写入或确认一条经验；有会话时把 key 填进简报 `raw/01-brief.md` 的“本次沉淀”，打包脚本会核对这些 key 在经验库里、且确认日期不早于会话创建日。本仓库另有 `render` 重新生成目录页 `experience/catalog.md`；个人数据只能用 `--store` 写进被 git 忽略的 `*.local.json`。

## 目录结构

```text
SKILL.md       技能入口：调用协议、路由、忠实原文规则、写作流程、每次调用后沉淀
references/    17 份写作指南（含封面与插图风格菜单）与规则卡定义 cards.json
assets/        阅读型 HTML 模板、正文格式示例、视觉生产简报（都是骨架，以规则卡为准）
scripts/       技能自检、文章打包、会话管理、经验库、规则卡及其测试
experience/    经验库 notes.json 与自动生成的 catalog.md
examples/      一篇完整的科技资讯示例（由 article builder 从示例正文生成）
evals/         人工评审方法与回归用例
```

## 五个技能的分工

| 技能 | 负责 |
| --- | --- |
| [Luz-System](https://github.com/luzern0414/Luz-System) | 产品系统设计：需求、方案、功能清单、产品界面、原型、硬件选型 |
| [Luz-Design](https://github.com/luzern0414/Luz-Design) | 视觉标准与版式：配色、字体、图标、海报、文档与表格排版 |
| [Luz-Dev](https://github.com/luzern0414/Luz-Dev) | 从设计到上线：后端、接口、数据库、部署、资质与验收 |
| [Luz-Writing](https://github.com/luzern0414/Luz-Writing) | 写作：起草、改写、核查、去机器腔、文章封面与插图 |
| [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl) | 检索与采集：用真实浏览器读取页面、媒体和评论 |
