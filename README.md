# Luz Writing

面向中文与英文写作的技能（Agent Skill）：起草、改写、润色、调研、核查事实、梳理结构和审读，覆盖科技资讯、营销文案、观点与科普、故事与小说、学术与专业文档，以及各平台的标题和格式适配。

## 能做什么

- **先定三件事再动笔**：写给谁、要他们做什么、凭什么相信；不清楚时先补齐任务简报。
- **事实可查**：数字、引语、日期、名称逐条对应来源；搜索摘要和内容农场只算线索，不当证据；不确定的内容明确标注，不编造数据、引语、评价或产品能力。
- **自然表达**：识别并改掉空泛、套话、排比堆砌和明显的机器腔，同时避免矫枉过正；没问题的句子原样保留。
- **只交付要的内容**：用户要几条、多长、什么格式就给什么，不附带建议、评分、改动说明或备选版本，除非用户要求。
- **成稿排版**：文章可以打包成一个自包含的阅读型 HTML，版式遵循 Luz Design 的阅读规范；需要封面或配图时走视觉生产流程。

## 典型用法

把本目录放进 Agent 的技能目录后，直接提需求，例如：

- “把这几条发布会信息写成一篇公众号科技快讯，配一张封面。”
- “这段介绍读起来太像机器写的，帮我改自然一点，只改这一段。”
- “给这个产品写三条小红书标题。”
- “核查一下这篇稿子里的数据和引语。”

## 工作方式

1. 判断任务类型，只读取对应的写作指南（共 17 份，按需加载）。
2. 需要时用 Luz Crawl 检索原始来源和参考文案，建立“说法—来源—限制”对照表。
3. 起草，再从大到小修订：主旨、结构、段落功能、论据、衔接、句子、用词、标点、平台格式。
4. 过质量关：事实、表达、格式和“只交付所要”的检查。
5. 需要文件时，每个任务放在独立目录，最终只交付一个 HTML。

## 目录结构

```text

assets/       阅读型 HTML 文章模板、正文格式示例、视觉生产简报
scripts/      会话管理、文章打包、技能自检
examples/     一篇完整的科技资讯示例
evals/        人工评审方法与回归测试用例
```

## 依赖

- Python 3.11 及以上。
- 调研依赖 [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl)；海报、页面与视觉设计依赖 [Luz-Design](https://github.com/luzern0414/Luz-Design)；配图为可选能力，需要本机的图像生成服务。
- 默认把产出写到 `D:\Codes\skill输出\Luz-Writing\`。

## 相关技能

[Luz-Design](https://github.com/luzern0414/Luz-Design) 负责版式与视觉；[Luz-Dev](https://github.com/luzern0414/Luz-Dev) 在上线时调用本技能撰写用户协议、隐私政策与上线文案；[HardwareMatch](https://github.com/luzern0414/HardwareMatch) 和本技能都通过 [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl) 做调研。
