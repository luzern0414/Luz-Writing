# 05 · 科技与 AI 资讯

## 目标

交付一篇日期明确、来源可追、事件之间有关系、读者看得懂的文章。它不是新闻标题合集，也不是把聚合页摘要换一种说法。

## 找料窗口

1. 从当前日期开始。
2. 当天素材足够时只写当天。素材不足再向前扩展，通常最多七天。
3. 写事件发生日期，不写“近日、最近、本周”来代替日期。
4. 聚合页发布日期不等于事件日期。
5. 过期但没有新进展的消息，不作为“今日新闻”重发。

## 选题优先级

1. AI 新能力：模型或工具能做以前不能做的事，或成本、速度变化让它进入新场景。
2. 真实部署：汽车、工厂、医疗、药物研发、政务、金融等具体地点、公司、流程与结果。
3. 方向性变化：开源、权重开放、收购、定价、政策、安全事件。
4. GitHub 热门项目：增长快、用途清楚、可访问，尤其是 Agent、工具链、推理与开发基础设施。
5. 公司动态、融资、股价：只有在直接说明技术或产品走向时入选。

一条候选无法与其他事件形成因果、递进或对照关系时，单独成篇或不写。

## 事实门

每条入选事件至少具备：

- 精确到日期的发生时间。
- 明确主体（公司、机构、项目）。
- 明确动作（发布、上线、开源、收购、部署、修复、被攻击）。
- 可访问来源。
- 至少一个可核查的产品名、数字、地点或版本（用于核查，不等于都要写进正文，见“数字预算”）。
- 官方一手来源，或两个独立可靠来源。

只有单一聚合页、截图、传闻或改写标题的内容，不写成确定事实。厂商自报性能保持“公司称”；第三方复测另写。

GitHub 项目还要检查：

- 仓库完整名称和可访问链接。
- 项目实际功能，不根据简介热词猜测。
- 当天星数或趋势信号及统计时间。
- 是否改名、转移、归档或停止维护。
- 热度与可用性不是一个指标。

## 工具顺序

1. 精确关键词搜索，找线索。
2. 打开官方新闻页、产品文档、监管或研究原文。
3. 打开独立报道，核对细节与反证。
4. 页面不可读时用可用的抓取工具；每次更换工具都保留结果来源。
5. GitHub 数字通过 API 或页面当天读取。

搜索不到不能自动等于事件不存在。更换准确名称、产品版本和语言再查；仍无法核实时标“待确认”。

## 逻辑编排

把事件按关系排列：

- **因果：** 成本下降，使某类设备可以部署。
- **递进：** 从聊天工具进入手机，再进入车与工厂。
- **对照：** 同一技术一边提升效率，一边扩大攻击面。
- **共同约束：** 三个事件都受数据、算力、监管或供应链限制。

话题之间写真实桥接。四种常用接法：

| 接法 | 写法 |
| --- | --- |
| 关键词桥接 | 下一段复用上一段的对象或结果 |
| 因果承接 | 上一段的后果成为下一段的条件 |
| 让步转折 | 先承认限制，再写新的证据 |
| 同类对照 | 直接切换另一个相似事件，指出差异 |

不要按“又一条、下一条、最后一条”排队。

## 正文骨架

资讯稿是讲给朋友听的新鲜事，不是数据简报。事实负责可信，表达负责让人读下去；两者缺一个，稿子都不成立。

**开头一段：** 用一个画面、比喻、反差或读者自己会遇到的场景进入，再在一两句内交代发生了什么。可以写“这几天的 AI 新闻有点像连续剧”这种带态度的开场，不写“今天有三件事值得关注”。

**单个话题：**

1. **一句话讲清事：** 谁做了什么，带日期，最多一个最关键的数字。
2. **翻译成读者的感受：** 用生活画面或类比说明它意味着什么，例如“以前得停车、翻邮箱、一个字一个字往导航里输的活，现在一句话完事”。
3. **替读者问一句、答一句：** 读者此刻最可能冒出的疑问或担心（“饭碗会不会被端走？”“听着像车机又多了个语音助手？”），然后给出基于事实的回答。
4. **落一句有态度的短评：** 口语、轻松、有判断，例如“真香”“先看个热闹”“好心办了坏事”。短评必须建立在已写事实上。

每段一到三句，一个意思。话题之间用“模型进了车，进工厂也就顺理成章”这类意义桥接，不用“另外、此外、同时”排队。

**结尾：** 落到普通人明天就会遇到的具体场景或一条具体提醒，例如“下次你扫码点奶茶，后台默默干活的那位‘AI 打工人’，就是这样一个便宜到没人注意的小模型”。不总结全文，不写空泛升华。

## 数字预算

数字是证据，不是内容。读者记不住一串数字，只会记住一个画面。

- **每个话题最多一到两个数字，全文通常不超过六个。** 只留读者读完会转述给别人的那个数字。
- **其余数字留在 `raw/02-claims.md`。** 核实过不等于要写进正文。
- **不复述排行榜。** 不写第一名多少、第二名多少、第三名多少；只说谁赢了、赢在哪、这对读者意味着什么。
- **百分比和环比尽量不写**，除非它就是新闻本身。需要表达涨跌时，说“翻了好几倍”“一周就冲到榜首”，前提是事实支持。
- **一个数字必须配一句翻译。** 例如“100 万 token 是什么量？差不多能把《三体》三部曲一口气吞下去”。翻译不了、读者无感的数字，删掉。
- **同一段不放两个以上数字**；一句话里只放一个。

## 归因写得像人话

核查的严谨留在 `raw/`，正文里只留一次自然的归因。

- 厂商自报的成绩，用一句轻松的话保持距离：“这些是厂商自己报的数，第三方还没复测，先看个热闹”。不要每个数字后面都挂“属于厂商自报”。
- 平台数据说一次口径即可（“这只是一个平台的数据”），不反复提醒。
- 不在正文里写“据某某报道”“按某某口径”“截至某日”的连串出处，除非出处本身就是新闻。

## 技术解释

先用读者已知的画面建立直觉，再补真实机制和边界。

- 好的类比让机制更容易看见，例如“说直白点，就是帮药企把一款新药从实验室到临床中间那一堆环节串起来”。
- 类比和事实有出入时，用半句话交代，不另起一段免责声明。
- 一个话题最多引入一两个关键概念；解释完一个再进入下一个。
- 不把厂商营销词当成技术机制。

## Luz 资讯声音

声音样本是 [02 · example body](../assets/02-example-body.txt) 的正文文字（只学文字，不用其中的图片路径）。写科技资讯前先读一遍，再动笔。可观察的手法：

| 手法 | 样本里的写法 |
| --- | --- |
| 带比喻的开场 | 这几天的 AI 新闻有点像连续剧 |
| 先猜读者的误解再纠正 | 听着像车机又多了个语音助手？这回不太一样 |
| 口语短评 | 真香；刻板印象拉满；属于是把“套娃”搬进了车间；好心办了坏事 |
| 有分寸的怀疑 | 这些是厂商自己报的数，第三方还没复测，先看个热闹 |
| 画面化收束 | 太仓这间车间，现在就是人形机器人的“产房” |
| 代价与好处并写 | 方便是真方便，代价也摆在明面上 |
| 生活场景结尾 | 下次你扫码点奶茶…… |
| 给普通人的具体提醒 | 点链接前多想一秒，防诈骗的第一步就是别手快 |

不照搬样本的句子和比喻，每篇换新的画面。口语短评每个话题一到两处，不要每段都抖机灵。

## 反例

下面这种写法事实全对，但不合格：

> 33.6 万亿摊到每天，大约 4.8 万亿。10 月 25 日这一天，1017 版就跑了 5.77 万亿，比前一天又多了 21%。

问题：一段三个数字、没有画面、没有态度，读者读完什么也记不住。改法：只留“一周 33.6 万亿 token”，再用一句话告诉读者这意味着什么，然后给一句短评。

## 标题与摘要

标题需要主语、动作或对象、真实依据与悬念。夸张的是语气，不是事实。

- 建议 30 个汉字以内，最终以渠道显示为准。
- 不用“震惊、惊天、炸裂”代替具体冲突。
- 可用结构：“时间范围 + 主体 + 反常识动作”或“主体 + 动作 + 具体悬念”。
- 每个标题断言能在正文找到证据。
- 原项目交付格式的摘要只写“谁做什么”，建议 25 个汉字以内；其他平台按渠道要求调整。

## 可选视觉包装

原 Luz 科技资讯线的视觉风格是横向 3D 潮玩、软陶质感的封面与话题分隔图。保留它作为可选品牌风格，不自动在每次写作中生成图片。需要封面、插图、海报或详细版式时，按 [14 · 视觉素材与设计排版](14-visual-production.md) 执行。

需要配图时：

- 先写出每张图的文章任务和对应话题；封面一张，话题变化处按需配一张。
- 通过本机 `D:\Codes\Imagegen` 生成无文字原始素材；先做 dry-run，再按用户明确的视觉交付执行。
- 主体居中或偏左，留白明确，宽幅可使用 16:9 或请求自定义 `2368x1008`，实际画幅以返回文件为准。
- 哑光软胶、磨砂塑料、真实接触阴影、低饱和配色。
- 不放文字、水印、真实品牌 Logo、生成界面或无法确认的产品。
- 保留原生图片和生成 JSON；另行裁切、压缩或转码时记录加工状态。
- 需要封面族、长页、海报或统一视觉系统时，结合本机 `D:\Codes\Luz-Design`。
- 生成后检查材质、颜色、裁切、实际比例和事实对应关系。

## 交付

成品只放正文。来源清单写进会话的 `raw/02-claims.md`，不进成品 HTML，也不默认贴进对话：

- 每条的标题、发布者、URL、事件日期、访问日期。
- GitHub 数字的查询时间。
- 仍为二手、待确认或被反驳的内容。
- 覆盖日期范围。

资讯素材优先用 Luz-Crawl 采集（`github`、`hackernews`、`x`、`google`、`bing` 等），采集合集导入 `raw/05-crawl/`，见 [16 · 输出路径、采集与排版](16-output-paths-and-tools.md)。用户要求附来源时，才在正文末尾或对话中给出来源清单。
