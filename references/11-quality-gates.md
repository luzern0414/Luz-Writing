# 11 · 质量闸门

## 先按任务选检查

| 任务 | 必需检查 |
| --- | --- |
| 草稿 | 主轴、结构、事实、声音、渠道 |
| 改写 | 原意、事实/数字/引语、范围、声音 |
| 定点编辑 | 改动范围、没有触碰范围外文本 |
| 审稿 | 有位置的问题、读者影响、最小修法 |
| 科技资讯 | 日期、来源、口径、冲突、读者影响 |
| 营销 | 可证明性、差异、CTA、合规 |
| 小说 | 因果、视角、场景变化、人物动机、连续性 |
| 学术 | claim-evidence、引用、术语、限制 |
| 发布文件 | 文件存在、结构完整、渲染/打开、大小 |
| 图片、海报或视觉排版 | 素材任务、实际比例、文字可编辑、视觉层级、素材权利、设计验收 |

## Gate 1 · 任务与范围

- 交付物和用户要求一致。
- 审稿没有被偷偷扩成改写；写作和改写没有被偷偷扩成审稿。
- 交付里没有用户没要的建议、改动说明、备选版本、风险提示或后续邀约（见 [15](15-deliver-only-what-was-asked.md)）。
- 定点编辑没有改动范围外文本。
- 计划、草稿、成品没有互相冒充。
- 未完成、未核验和不确定内容没有写成完成。

## Gate 2 · 事实与证据

逐项核对：

- 数字是否有来源、定义、时间和单位。
- 日期是事件日期还是页面发布日期。
- 人物、产品、版本、机构和职位正确。
- 引文与原文一致，上下文没有反转。
- 因果没有被写成相关性。
- 来源支持的是当前断言，不只是大致主题。
- 反证没有被隐藏。
- 二手来源与厂商自报保持口径。
- 预测、目标和已发生事实分开。
- 没有新增无法追溯的事实、评价、案例或 CTA 承诺。

高风险内容把核心声明逐条写进 `raw/02-claims.md`，列与状态词按 [02 · Claim log 与声明分级](02-evidence-and-fact-checking.md)。

## Gate 3 · 原意与保真

改写前后对照：

- 谁做什么没有变化。
- 否定、条件、范围、时态、完成状态和程度没有偷换。
- 数字对应原对象，不是看起来相似的指标。
- 抽象描述仍可保持抽象，不被擅自具体化。
- 责任归属和来源没有被拿走。
- 下一步、承诺和邀请没有变成命令。
- 受保护文本、代码、公式、路径、标识符和引用未被改动。

不确定是否能等义简化时，保留原句。

## Gate 4 · 结构与逻辑

反向提纲：

1. 每段一句主旨。
2. 删除某段是否丢信息。
3. 每段是否支撑全文主轴。
4. 相邻段的关系能否用因果、递进、对照、选择或后果说出。
5. 标题、摘要、引言、结论是否承诺了正文兑现的内容。

常见结构问题：

- 背景过长，核心事实在后面。
- 同一意思拆成多段。
- 每一节都套相同模板。
- 结论引入新事实。
- 事例只被解释，不改变风险、信息、关系或判断。
- 文档有内容，但没有负责人、条件、结果与下一步。

## Gate 5 · 自然表达

在语境里检查，不按词频机械删词：

- 对比句是否真实需要两半。
- 独立短段是否新增事实。
- 三项列表是否真的有三项。
- 段首、句长、段落长度和章节形状是否机械重复。
- 抽象词是否替代了具体对象与动作。
- 署名权威是否有名字和说法。
- 格式化强调是否过度。
- 对话式工作残留、知识截止声明和改写说明是否误入成品。
- 是否为了显得自然而加入假经历、假情绪或假细节。

发现问题时重写结构。不要给禁用词做同义词换皮。按 [17 · AI 痕迹模式目录](17-ai-pattern-catalog.md) 第九节的顺序自检，并确认没有矫枉过正：改后没有变长、没有新增事实、没有统一成假口语。

### 表达检查（公众号、小红书、短视频、观点与科普必做）

- 数字预算：每个话题最多一到两个数字，同一段不超过两个，不复述排行榜；事件日期、版本号不计（科技资讯见 [05](05-technology-news.md)“数字预算”）。
- 每个话题至少有一个画面或类比、一句有态度的短评。
- 开头有画面、比喻或反差；结尾落到读者的具体生活场景或具体提醒。
- 正文里的出处和口径说明只出现在必要的那一次。
- 朗读一遍：像跟朋友讲，而不是念简报。

## Gate 6 · 声音

- 有样本时，比较句长分布、人称、语气词、标点、开场和转场，不靠单句印象。科技资讯默认样本是 `assets/02-example-body.txt` 的正文文字。
- 保留用户用词和重点，不把个人表达升级成公司语言。
- 改写不自动增加幽默、热情、决断或第一人称。
- 中文与英文分别按目标渠道校对，不做逐字翻译腔。
- 小说和非虚构的声音边界不同；非虚构不能为了“好听”虚构。

## Gate 7 · 渠道

- 标题、摘要、首段和 CTA 一致。
- 字数在硬限制内。
- 平台格式被实际实现，不只写在说明里。
- 小红书标签、邮件主题、SEO 字段等没有遗漏。
- 社媒帖不残留网页 Markdown。
- 视频稿读出声能顺。
- 高转化页面把证明、异议处理和下一步放在读者需要的位置。

## Gate 8 · 审稿报告格式

只在用户明确要求审稿、挑问题或诊断时使用；写作、改写、润色请求不输出这张表：

| 优先级 | 位置/引文 | 问题与读者影响 | 建议 | 证据状态 |
| --- | --- | --- | --- | --- |
| 必须改/建议改/可不改 | 可定位原文 | 具体损失 | 最小动作 | 02 › 声明分级的状态 |

优先级：

- **必须改：** 事实错误、核心逻辑断裂、误导、合规或发布阻塞。
- **建议改：** 明显影响理解、节奏、可信度或渠道效果。
- **可不改：** 风格偏好，只有一句解释，不假装客观错误。

没有明显问题就直说。不要为凑数量挑错，也不要把个人偏好伪装成硬规则。

## Gate 9 · 文件交付

- 产物位于 `D:\Codes\skill输出\Luz-Writing\NNN-主题\`，根目录只有 `NNN-主题.html` 和 `raw/`，`03-session.py check` 通过。
- 成品 HTML 通过 `D:\Codes\Luz-Design\scripts\check_document.py`，零错误。
- 输出路径真实存在。
- 编码 UTF-8，文件名清楚。
- Markdown 链接、图片和引用路径有效。
- HTML 在浏览器打开，正文与插图完整；第一行是标题，没有摘要、来源区或说明文字。
- Word、PDF 等导出文件的页数、目录、字体、表格与分页按 Luz-Design 的 `docx`、`pdf-markdown` 规则卡检查（`py -X utf8 D:\Codes\Luz-Design\scripts\context.py docx`）。
- 未运行的验证用一句话说明，不把“已生成”说成“已验证”。

## Gate 10 · 视觉素材与版式

需要配图、海报或设计排版时，完整执行 [14 · 视觉素材与设计排版](14-visual-production.md)。

- 每张图承担明确阅读任务，并与对应段落一致；没有把生成图当作新闻、用户、产品或评价证据。
- Imagegen 提示词和首次运行记录可追溯，实际尺寸、格式与 warnings 已核实。
- 生成图不含乱码文字、水印、Logo、错误界面和不必要装饰；精确文字位于可编辑层。
- 封面、正文图和缩略图在目标渠道都能识别主体；裁切没有破坏信息。
- 使用 Luz-Design 时，主要信息、视觉层级、安全区、对比度和导出验收已通过。
- HTML 或设计文件重新打开后，图片路径、复制区、图注、替代文本和大小均可用。

## 交付前快速提问

1. 读者看完会知道什么、相信什么、做什么？
2. 哪个句子一旦失去证据就危险？
3. 哪段可删而读者不损失？
4. 标题是否比正文承诺更多？
5. 这段是否像本人会写，还是像任何模板都能生成？
6. 现在最不确定的是什么，是否已如实标出？
