# 07 · 观点与科普

## 观点文

观点内容至少给读者一项价值：更准确的理解、新的解释框架、可执行判断，或一个被具体材料击中的感受。

### 结构

1. **入口。** 一个具体场景、事实、问题或反直觉数字。
2. **命题。** 前几句让读者知道正在争论什么，不先写“有人认为…也有人认为…”。
3. **拆前提。** 共识依赖哪些没有说出的假设？
4. **证据与反证。** 哪些事实支持，哪些情况打破？
5. **判断。** 给出可检验的解释，不只列现象。
6. **边界。** 在哪个范围内成立，哪里仍不确定。
7. **收束。** 回到具体后果、行动或未完成的问题。

可使用场景体，但场景不是论证的装饰。每个场景都应推进理解或改变判断。

### 思考工具

- **命名：** 给反复出现的现象一个短名称，再用具体例子定义它。
- **生产者视角：** 谁做、谁付钱、成本在哪、谁承担后果。
- **金钱/激励流向：** 每个参与者为什么这样做。
- **反常识拆解：** 找共识中的隐含前提，不用“所有人都错了”制造刺激。
- **二分与连续：** 只有两类真实不同才做二分；程度问题用区间和条件。
- **边界案例：** 主动找会推翻判断的反例。

### 真实性

个人经历只在用户提供或确认时使用。需要生活和情绪细节而材料不足时，标记缺口或改成不以亲历为依据的论证。不能为了“有代入感”虚构人物、对话、收入、病情、客户或家庭冲突。

## 科普与解释

目标不是让读者背术语，而是读完能用自己的话解释机制，并知道哪里还不知道。

### 四步

1. **先画面后术语。** 用一个读者见过的对象或过程建立直觉。
2. **一层一个概念。** 解释完一个，再进入下一个。
3. **类比后补机制。** 说明类比哪里准确、哪里不准确。
4. **诚实标边界。** 区分共识、争议、未知和适用条件。

结构：

> 反常识现象 → 已有直觉 → 类比 → 真实机制 → 例子/数字 → 边界 → 可带走的解释

### 新概念数量

一篇面向大众的解释通常围绕三到五个新概念。术语越多，阅读负担越大。没有必要出现的概念移到下一层或删掉。

### 精确性

- 数字给口径、单位和时间。
- 机制写清输入、处理、输出、约束和失败情况。
- 不把相关性写成因果。
- 不把厂商宣传词当作技术定义。
- 高风险领域只说明原理，不代替专业建议。

## 观点与故事的选择

| 读者想要 | 主结构 |
| --- | --- |
| 被说服 | 命题、证据、反证、边界 |
| 想弄懂 | 类比、机制、边界 |
| 被代入 | 场景、选择、后果、留白 |
| 要行动 | 判断、条件、步骤、验证 |

可以混合，但必须有一个主轴。故事开场后进入论证，或论证中插入场景，都不能让两种结构互相抢主线。

## 质量检查

- 核心判断能否一句话说清？
- 是否提供了读者自己想不到的因果或边界？
- 每个场景、数字和案例都承担论证职能吗？
- 是否把相关当因果、把传闻当共识？
- 类比是否误导？之后有没有补真实机制？
- 情绪和反问是否跟着事实，而不是替代事实？
- 结尾是否给了新的理解、行动或具体后果？
