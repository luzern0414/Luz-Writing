# 12 · 声音档案与持续学习

## 从样本中读出什么

给定真实写作样本时，先做可观察的测量，再动笔：

| 维度 | 观察 |
| --- | --- |
| 正式/口语 | 缩略、口语词、句末语气、称呼 |
| 抽象/具体 | 场景、数据、名词与评价词的比例 |
| 收敛/铺陈 | 平均与变化幅度、段落长度 |
| 克制/外放 | 自我评价、情绪、玩笑、感叹 |
| 人称 | 第一、第二、第三人称何时出现 |
| 句式 | 常用起句、并列、反问、插入语、省略 |
| 标点 | 破折号、省略号、引号、括号、分号 |
| 转场 | 靠事实、问题、场景还是抽象连接词 |
| 重点方式 | 加粗、标题、黑话、重复、类比 |
| 收尾 | 事实、行动、余韵、问题、格言 |

不要用“专业一点、自然一点”替代测量。样本互相矛盾时，以当前任务、体裁和最新确认偏好为准。

## 五个可调维度

给长期项目记录 1 到 10 的自定义刻度，例如：

- 正式 1 ↔ 口语 10。
- 专业 1 ↔ 通俗 10。
- 克制 1 ↔ 外放 10。
- 简洁 1 ↔ 展开 10。
- 中性 1 ↔ 有立场 10。

刻度是沟通工具，不是写作公式。不同文体可以各有档案。

## 何时更新长期规则

满足任一条件：

- 用户明确说“以后都这样”“记住这个偏好”。
- 用户在多个任务中重复纠正同一模式。
- 用户提供稳定样本，并指定它为目标声音。
- 现有规则已被用户明确推翻。

不把以下内容自动写成长期偏好：

- 单篇长度。
- 一次活动的临时禁令。
- 当前文章里某个事实或角色。
- 用户对一次输出偶然的措辞选择。
- 敏感个人信息或未经授权的第三方资料。

## 规则记录格式

通用的偏好、教训和有效信息写进经验库 `experience/notes.json`，用 `scripts/04-experience.py note` 按 key 更新：同一话题只留一条，新说法替换旧说法，旧文自动留一条 `previous` 备查。一次调用里学到的东西在结束前写入，下次调用开始先 `search`。

某个写作项目专属的文风，优先追加到该项目的文风档案；用户明确要求修改本 Skill 包时，才追加到本文件末尾的“项目规则”区：

> 日期 · 规则 · 适用文体/渠道 · 触发条件 · 短正例 · 短反例 · 来源（用户确认/样本/反复修改）

一条规则只表达一个可执行选择。新规则推翻旧规则时直接替换，注明日期和适用范围，不让两条矛盾的规则并存。

## 比较原稿与终稿

不要只收集句子差异。按四层看：

1. **内容：** 用户删了哪类信息，加入了哪类证据。
2. **结构：** 用户保留哪些段落，合并哪些意思。
3. **语气：** 用户在哪些位置变得直接、克制、幽默或具体。
4. **表层：** 哪些词、标点、句长被反复调整。

至少在两个独立样本出现同一模式，才提升为候选规则。一次修改只说明眼前文本需要它。

## 改写时如何落声

1. 保留用户已有的论点、词汇、重点与省略。
2. 用档案校准句长、人称、转场和收尾。
3. 不照搬样本内容、独特比喻或私人经历。
4. 用户样本与通用去 AI 规则冲突时，服从样本；样本本身的问题只在用户要求审稿时指出。
5. 没有样本时，按渠道、关系、目标和题材选择中性档位，不假装是用户本人。
