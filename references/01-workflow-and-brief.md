# 01 · 工作流与写作简报

## 先锁定交付对象

在动笔前把请求归到一个明确对象。对象决定授权范围和停点。

| 对象 | 交付 | 不自动扩成 |
| --- | --- | --- |
| 从零起草 | 可直接使用的初稿 | 研究全部背景、发布、配图 |
| 改写 | 改后全文 | 新事实、新经历、新结论 |
| 定点修改 | 指定句子或段落 | 全文重写、结构重排 |
| 审稿 | 有位置和依据的问题清单 | 未经要求直接改稿 |
| 策划 | 选题、结构、内容矩阵 | 整篇成稿 |
| 调研 | 带来源的发现与不确定性 | 把线索写成事实 |
| 发布包 | 标题、摘要、正文、渠道信息 | 发布到外部平台 |

当同一请求同时包含多个对象，只完成其明确要求。例如“看看这篇”通常先审稿；“改到可以发”允许实质改写，但只交改后全文，不附审稿意见，也不能编造缺失事实。无法判断哪个授权成立时，问一个二到四选项的简短问题，不写开放式长问卷。

## 简报的最小充分集

先使用用户已经给出的信息。只有缺失项会实质改变结果时，才问一到三个问题。

| 项目 | 要确认的内容 |
| --- | --- |
| 读者 | 谁读；已经知道什么；为什么会读 |
| 目的 | 理解、相信、行动、记住、娱乐、通过评审 |
| 渠道 | 公众号、网页、广告、邮件、短视频、论文、内部文档 |
| 关系 | 陌生、同行、客户、上级、编辑、读者 |
| 事实材料 | 已给来源、附件、数据和必须保留的原文 |
| 声音 | 参考样本、品牌语气、本人声音、中性说明 |
| 约束 | 字数、格式、截止时间、禁用词、合规与品牌规则 |
| 成功标准 | 读者看完能回答什么、做什么，或评审要接受什么 |

没提供字数时按渠道和任务体量给合理默认；不要用固定字数代替编辑判断。用户给的硬约束优先于平台常识。

## 起草前的一句话

用一句话写出作品的主轴。写不出来时，缺的是素材或判断，不是措辞。

- 资讯：发生什么，为什么值得现在读，和读者有什么关系。
- 观点：主张 X，因为 Y，边界是 Z。
- 科普：先让读者看见 A，再解释 B，并明确 C 仍未知。
- 营销：对处于 S 场景的 R，产品产生 O，因为证据 M，下一步是 A。
- 叙事：角色想要 W，受阻于 O，必须作出选择 C，并承担结果 R。
- 学术：问题 Q 存在，现有研究缺少 G，本文用 M 提供 E，贡献是 C，限制是 L。
- 文档：读者需要作出决定或完成操作，文档必须给出条件、步骤、结果和例外。

主轴包含未确认事实时，先标 `[待核实]`。不要用漂亮措辞遮住空缺。

## 写作的五段推进

1. **定材料。** 把确定事实、用户判断、推测和缺失证据分开。高风险内容建立 claims 表。
2. **定顺序。** 选择因果、递进、对照、问题解决、决策或叙事顺序。相邻段落应通过含义相连。
3. **写成段落。** 每段只推进一个意思。首句负责方向，末句交出事实、选择、后果或下一步。
4. **由大到小改。** 先看承诺是否兑现，再看结构、段落、句子、用词和标点，最后做平台格式。
5. **如实交付。** 草稿给成品；审稿给问题；研究给来源；无法核验的内容写在正文外或使用可见缺口标记。

## 输出契约

### 新稿

直接交成品。不附创作过程、规则清单、自我评价、假设说明或备选版本，规则见 [15 · 只交付要求的文案](15-deliver-only-what-was-asked.md)。

### 改写

只交改写稿。不附改动清单、前后对照或修改理由；用户要求“说明改了什么”时才写。

### 定点编辑

只交修改后的指定部分。不附理由，不指出范围外的其他问题。范围外内容原样保留。

### 审稿

按影响排序，不使用平均分掩盖关键缺口。每条写清：

1. 原文位置或短引文。
2. 读者会怎样误解、卡住或失去信任。
3. 最小可行修法。
4. 缺失资料时，说明什么证据能解除限制。

### 调研与发布包

调研给结论和来源；claim-evidence 表、访问日期、冲突证据写进会话的 `raw/02-claims.md`，用户要求时才在对话里展开。发布包只交用户要的字段：标题、摘要、平台字段、图片说明。

## 何时停下来问

只在这些信息无法从上下文合理补足时停下：

- 作品的核心立场或主角目标缺失。
- 指定事实互相冲突，选哪一个会改变结论。
- 用户要求引用、数据或经历，但材料中完全没有。
- 渠道字数或格式是硬限制，却又互相矛盾。
- 高风险写作需要具体责任主体、法域或截止日期。

可以合理假设的细节直接处理，不在交付时解释假设，不让用户承担重复劳动。
