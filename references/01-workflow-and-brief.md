# 01 · 工作流与写作简报

## 0 · 规则卡与经验优先

动笔前先运行 `py -X utf8 scripts/06-context.py <任务类型>`（`list` 看全部类型），读完整张规则卡：用户偏好（全部遵守）、相关教训、本类任务的写作指南原文、该用的工具和交付前检查。模板、示例正文和打包脚本只是骨架，与规则卡冲突时按规则卡。

- 建会话时 `03-session.py new --topic "主题" --card <类型>` 把规则卡存进 `raw/00-rules/`；读完后在 `raw/01-brief.md` 的“采用的规则”逐行写出本次落实了哪些小节或偏好 key。没有当前规则卡或这张表为空时，`02-article_builder.py` 拒绝打包。
- 没有会话的对话回复同样先读规则卡，只是回复里仍然只给文案，不提规则卡（[15 · 只交付要求的文案](15-deliver-only-what-was-asked.md)）。
- 再用 `04-experience.py search <关键词>` 按话题和渠道查经验库；规则卡已带上全部偏好和匹配的教训，查库补的是本次话题的细节。
- 结束前用 `04-experience.py note` 至少写入或确认一条经验（新偏好、规则纠正、有效写法、调研来源与范围、生成参数；已有经验再用上就用同一 key 再写一次），会话里把 key 填进 `raw/01-brief.md` 的“本次沉淀”，打包脚本会核对。没有会话的对话回复同样要写。

## 先锁定交付对象

在动笔前把请求归到一个明确对象。对象决定授权范围和停点。

| 对象 | 交付 | 不自动扩成 |
| --- | --- | --- |
| 从零起草 | 可直接使用的初稿 | 研究全部背景、发布、配图 |
| 改写 | 改后全文 | 新事实、新经历、新结论 |
| 定点修改 | 指定句子或段落 | 全文重写、结构重排 |
| 审稿 | 有位置和依据的问题清单 | 未经要求直接改稿 |
| 策划 | 选题、结构、内容矩阵 | 整篇成稿 |
| 调研 | 带来源的发现与不确定性 | 把线索写成事实 |
| 发布包 | 标题、摘要、正文、渠道信息 | 发布到外部平台 |

当同一请求同时包含多个对象，只完成其明确要求。例如“看看这篇”通常先审稿；“改到可以发”允许实质改写，但只交改后全文，不附审稿意见，也不能编造缺失事实。无法判断哪个授权成立时，问一个二到四选项的简短问题，不写开放式长问卷。

## 简报的最小充分集

先使用用户已经给出的信息。只有缺失项会实质改变结果时，才问一到三个问题。

| 项目 | 要确认的内容 |
| --- | --- |
| 读者 | 谁读；已经知道什么；为什么会读 |
| 目的 | 理解、相信、行动、记住、娱乐、通过评审 |
| 渠道 | 公众号、网页、广告、邮件、短视频、论文、内部文档 |
| 关系 | 陌生、同行、客户、上级、编辑、读者 |
| 事实材料 | 已给来源、附件、数据和必须保留的原文 |
| 声音 | 参考样本、品牌语气、本人声音、中性说明 |
| 约束 | 字数、格式、截止时间、禁用词、合规与品牌规则 |
| 成功标准 | 读者看完能回答什么、做什么，或评审要接受什么 |

没提供字数时按渠道和任务体量给合理默认；不要用固定字数代替编辑判断。用户给的硬约束优先于平台常识。

## 起草前的一句话

用一句话写出作品的主轴。写不出来时，缺的是素材或判断，不是措辞。

- 资讯：发生什么，为什么值得现在读，和读者有什么关系。
- 观点：主张 X，因为 Y，边界是 Z。
- 科普：先让读者看见 A，再解释 B，并明确 C 仍未知。
- 营销：对处于 S 场景的 R，产品产生 O，因为证据 M，下一步是 A。
- 叙事：角色想要 W，受阻于 O，必须作出选择 C，并承担结果 R。
- 学术：问题 Q 存在，现有研究缺少 G，本文用 M 提供 E，贡献是 C，限制是 L。
- 文档：读者需要作出决定或完成操作，文档必须给出条件、步骤、结果和例外。

主轴包含未确认事实时，先标 `[待核实：缺什么]`。不要用漂亮措辞遮住空缺。

## 写作流程

新稿和实质改写按这个顺序做；改稿时先按 [04 · 自然表达](04-natural-expression.md) › 改稿边界 判断能改多少。

1. **定材料。** 把确定事实、用户判断、推测和缺失证据分开。高风险内容建立 claims 表（[02 · Claim log](02-evidence-and-fact-checking.md)）。
2. **定主轴。** 用上一节的一句话写出主轴。
3. **定顺序。** 选择因果、递进、对照、问题解决、决策或叙事顺序。相邻段落通过含义相连，从上一节的结果搭桥，不靠“接下来”预告转场。
4. **写成段落。** 每段只推进一个意思。首句负责方向，末句交出事实、选择、后果或下一步；句子长短跟着意思走。
5. **由大到小改。** 先看承诺是否兑现，再看结构、段落、句子、用词和标点，最后做平台格式。
6. **过闸门。** 按 [11 · 质量闸门](11-quality-gates.md) 选检查。发现 AI 痕迹时改结构，不换同义词；没标记的句子逐字保留，只清理一轮，不加事实和长度（[17](17-ai-pattern-catalog.md) › 一）。
7. **如实交付。** 交什么、不交什么按 [15 · 只交付要求的文案](15-deliver-only-what-was-asked.md)；审稿报告的格式见 11 › Gate 8；调研的 claims 表留在 `raw/02-claims.md`，对话里只给结论和状态。

## 何时停下来问

只在这些信息无法从上下文合理补足时停下：

- 作品的核心立场或主角目标缺失。
- 指定事实互相冲突，选哪一个会改变结论。
- 用户要求引用、数据或经历，但材料中完全没有。
- 渠道字数或格式是硬限制，却又互相矛盾。
- 高风险写作需要具体责任主体、法域或截止日期。

可以合理假设的细节直接处理，不在交付时解释假设，不让用户承担重复劳动。
