# 10 · 渠道与格式

平台规则与界面限制会变化。以下用于规划，最终以用户当前要求和平台最新规则为准。

## 微信公众号

- 标题通常 15 到 25 个汉字，可从冲突、反差、画面、利益或具体事件切入；数字最多一个。用户要几个给几个，没说数量给一个。
- 摘要可独立成立，约 50 到 120 个汉字；科技资讯若要事实摘要，可按 25 个汉字以内的紧凑格式。
- 正文用短段、清楚层级和可扫读结构。小标题命名内容，不写“接下来”。
- 长文开头可用事件、故事或问题，但要尽快进入主题。
- 结尾给下一步、具体后果或明确期待；减少空泛总结。
- 标题、摘要在分享卡片中要能成立，不依赖正文上下文。

## 小红书

- 标题通常 20 个汉字以内，突出场景、结果、数字、反差或避坑。
- 正文口语化，但不要使用过时套话和机械 emoji。
- 结构可写：结论/场景 → 分点 → 真实细节/证据 → 保存或评论理由。
- 标签 3 到 6 个，与内容直接相关。
- 个人体验必须真实；没有经历时改写为教程、信息整理或明确标注的示例。

## 抖音、视频号、短视频

- 开头 1 到 3 秒给问题、冲突、结果或画面，不寒暄。
- 一句一个动作或信息，便于字幕与剪辑。
- 结构：钩子 → 场景/问题 → 解决或演示 → 证据 → 行动。
- 字幕写可读、可截取的短句，不把长书面句硬切。
- 标题、描述和封面一致兑现内容，避免标题承诺正文没有。
- 口播稿要读出声，检查换气、同音歧义和连续信息密度。

## 朋友圈

- 一到三句或一小段，一屏内读完。
- 从真实场景或个人观察进入，再接产品或信息。
- 活动写清时间、参与方式和真实条件。
- 图片承担主要信息时，文字补背景或情绪。

## 电商详情页

按屏分配：

1. 首屏：主结果/差异 + 人群或场景。
2. 痛点：二到三个真实困扰。
3. 解决：功能 → 机制 → 利益。
4. 证据：参数、材料、测试、授权评价。
5. 信任：售后、资质、真实案例。
6. 选购：适用人群、规格、比较。
7. CTA：行动 + 获得 + 风险/条件。

参数、库存、保障和价格必须来自真实材料。感官形容词后要有可核查的对象。

## 广告语与 Slogan

- 通常越短越好，但不必强行四到十二字。
- 包含品牌主张、品类线索或使用场景中的至少一项。
- 读出声检查节奏、歧义、谐音和可替换性。
- 给不同方向而非一个句子的同义词变体。
- 检查竞品能否原样使用；可以时回到独特机制。

## 海报与活动

信息层级：

> 主标题/核心事件 → 关键利益 → 时间地点 → 参与条件 → 行动

远距离先读到主体，小字承担条件和说明。高对比留给真重要的信息，不用所有句子争抢。

## 邮件与推送

- 主题行突出读者相关性或实际价值；不为打开率制造假悬念。
- 预览文字补充主题，不重复。
- 一封邮件一个主要 CTA。
- 推送一句话说清事情，避免“点开才知道”。
- 退订、隐私、费用、频率与授权按实际政策写。
- 序列邮件每封推进一个阶段：欢迎、问题、机制、证据、异议、行动。

## LinkedIn、X/Twitter、Reddit、Hacker News

### LinkedIn

- 第一行单独承担钩子和承诺。
- 用具体工作场景、判断或结果，不写泛化励志故事。
- 段落短，留出扫读空间；标签少而相关。

### X/Twitter

- 单条给一个可独立理解的观点或事实。
- 长线程每一条都有新信息；不是把长文一句一段复制。
- 删除跨平台 Markdown 语法，检查当前字数限制。

### Reddit

- 先读社区规则、置顶和近况，按真实社区语气写。
- 说明身份、目的与利益关系；不做隐形推广。
- 提交能独立提供价值的内容，而不是先导流。

### Hacker News

- Show HN/Ask HN 直接说做了什么、为什么、限制与如何试用。
- 标题克制，避免营销词。
- 不隐藏商业关系，不把未完成能力写成已上线。

## SEO 与网页文章

- 标题匹配搜索意图与正文承诺。
- 开头直接回答主要问题，再补背景。
- 小标题使用读者会搜索的具体名词。
- 提供信息增量：数据、样本、案例、工具、清晰比较或真实经验。
- 内链要帮助继续阅读；不为关键词堆链接。
- 元标题、描述、URL 与正文一致，长度按当前工具提示检查。
- 更新旧文时记录事实变化，不偷偷换掉原有数据。

## 文章 HTML 交付

需要封面、插图、海报或较完整的视觉版式时，先按 [14 · 视觉素材与设计排版](14-visual-production.md) 准备素材，再进入以下 HTML 流程。使用 `scripts/02-article_builder.py` 时，正文格式：

- 空行分段，一段一个 p。
- 单独一行 `[img] 绝对路径` 插入图片；第一张为封面。
- 行首 `> ` 生成提醒块。
- `**文字**` 加粗，`==文字==` 高亮。
- 其余内容做 HTML 转义，不按完整 Markdown 渲染。
- 图片以内联 base64 嵌入，控制文件大小。
- 发布前检查 HTML 可打开、复制区域完整、图片无缺失、文件在大小限制内。
- 记录图片的实际尺寸、格式、生成 JSON、图注、替代文本和加工状态。

## 渠道适配原则

同一核心事实与判断可跨渠道复用；入口、长度、节奏、视觉和 CTA 要按渠道重写。不能把公众号全文直接切成推文，也不能把广告 CTA 原封不动塞进科普文章。
